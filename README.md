# Business Management System (BMS)

An admin system for client projects, timelines, invoicing and a dashboard. Built with Laravel 13, a Vue 3 SPA, and MySQL 8.

**Modules (v1):** Dashboard · Project Management (clients, projects, tasks, milestones, Gantt timeline, activity log) · Invoicing (line items, server-side totals, payments, PDF, company settings).

**Not in v1:** payroll, CRM, inventory, multi-tenancy, notifications.

---

## Requirements

- PHP 8.3+ (tested on 8.4) with `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `intl`, `zip`
- Composer 2
- Node.js 20+ and npm
- MySQL 8.0+ (InnoDB, `utf8mb4`). The development machine used MariaDB 10.4; verify on MySQL 8 before release.

## Setup

```bash
composer install
npm install

cp .env.example .env
php artisan key:generate

# Create the database first (utf8mb4), then:
php artisan migrate --seed

php artisan storage:link   # company logo files
npm run dev                # Vite dev server (keep it running)
php artisan serve          # http://localhost:8000
```

Open http://localhost:8000 and sign in with a demo account (below).

For a production build: `npm run build`.

## Environment variables

See `.env.example`. The important ones:

| Variable | Notes |
|---|---|
| `APP_KEY` | Generated by `php artisan key:generate`. Never commit it. |
| `APP_URL` | Public URL of the app |
| `APP_TIMEZONE` | `Asia/Kuala_Lumpur` (invoice dates and "this month" figures use it) |
| `DB_*` | MySQL 8, `utf8mb4` |
| `SANCTUM_STATEFUL_DOMAINS` | Every host **and port** the SPA is served from, for example `localhost:8000`. If the port is missing, login fails with a 500. |
| `SESSION_DRIVER` | `database` |
| `SESSION_DOMAIN` | Your domain in production (or blank for the current host) |

## Default logins (development only)

| Role | Email | Password |
|---|---|---|
| Admin | `admin@example.com` | `password` |
| Staff | `staff@example.com` | `password` |

The seeders skip themselves when `APP_ENV=production`. Change these passwords, or remove the seeders, before any shared deployment.

## Demo data

`php artisan migrate --seed` loads:

- 5 clients, 8 projects (across planning, active, on hold, completed and cancelled), tasks and milestones
- 15 invoices across several months, with payments. Three are overdue.

Re-running the seeder does nothing if the demo data is already there.

## Scheduler (overdue invoices)

`invoices:mark-overdue` runs daily at 00:10 and marks unpaid, past-due invoices as `overdue`. Add one cron entry on the server:

```cron
* * * * * cd /path/to/SBMS && php artisan schedule:run >> /dev/null 2>&1
```

Run it once by hand to check: `php artisan invoices:mark-overdue`.

## Roles

| Action | Admin | Staff |
|---|---|---|
| View dashboard, clients, projects, invoices | yes | yes |
| Create and edit clients, projects, tasks, milestones | yes | yes |
| Create, edit, send, cancel invoices; record payments | yes | yes |
| Delete clients or projects; delete draft invoices | yes | no |
| Manage users and company settings | yes | no (read-only) |

The rules are enforced on the server with Policies. The UI hides what a role cannot do, but the API is the authority.

## Invoicing rules

- Numbers are `INV-YYYY-NNNN`, sequential per year. Projects are `PRJ-YYYY-NNN`.
- Totals are calculated on the server in integer cents. The UI shows a live preview, and the server's figures win.
- Discount is a fixed amount, applied before tax. Tax rate is a percentage.
- Once an invoice is sent, its items and amounts are locked. Only notes and terms can change.
- To undo an invoice, cancel it (not allowed once a payment is recorded). Deleting is only for drafts.
- Payments can't exceed the outstanding balance. Recording a payment moves the invoice to `partially_paid` or `paid`.

## Tests

```bash
vendor/bin/pest          # backend feature and unit tests (needs the bms_test database)
npx vitest run           # frontend unit tests
npm run build            # production build
vendor/bin/pint --test   # formatting
```

The test database is `bms_test`, set in `phpunit.xml`. Create it before the first run:

```sql
CREATE DATABASE bms_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## Deploy (generic VPS: Nginx + PHP-FPM + MySQL 8)

1. Clone the repository and run `composer install --no-dev --optimize-autoloader`.
2. Run `npm ci && npm run build`.
3. Copy `.env.example` to `.env`, set `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL`, the database, and `SANCTUM_STATEFUL_DOMAINS`.
4. Run `php artisan key:generate`, `php artisan migrate --force`, `php artisan storage:link`.
5. Run `php artisan config:cache && php artisan route:cache && php artisan view:cache`.
6. Point the Nginx document root at `public/`, and add the scheduler cron entry above.
7. Create the first admin by hand, or set its password after seeding. The seeder does not run in production.
